# My GitHub Release

I have organized these experiments as **v2.0.0**. The recommended repository name is `trec-covid-judgment-coverage`. This English-language edition is identified by the release tag `v2.0.0-en`.

Suggested repository description: `My TREC-COVID document-selection experiments: 12 configurations, pilot-to-full-query tracking, and offline reproducible evaluation.`

## Publication Procedure

I first create an empty GitHub repository and select its visibility. From the local repository root, I then add the repository URL provided by GitHub:

```bash
git remote add origin <repository-URL-provided-by-GitHub>
git push -u origin main
git push origin v2.0.0-en
```

These publication instructions are prepared for use; the current deliverables are the local repository and the upload archive. The local repository retains the experimental history. The archive generated by `git archive`, `trec-covid-judgment-coverage-v2.0.0-english-final-github.zip`, contains only the public files of this English-language edition of v2.0.0.

I use `.gitignore` to retain historical backups, article text, embedding caches, and virtual environments locally. A Git push and the supplied upload archive provide the same verified set of public files.

## Release Summary

I began with five queries, extended the analysis to 50 queries, and then compared fusion, random subsets, MMR, query expansion, learned sparse retrieval, a second dense model, and cross-encoder reranking. I report judgment coverage, observed relevance metrics, set overlap with BM25, and precision bounds for fixed rankings separately. I also use two set-preserving experimental comparisons to examine the relationship between selecting a document set and changing its prefix ordering.

After upload, GitHub Actions recomputes the results on push, pull request, and manual triggers. The local verification procedure and its results are documented in [RELEASE_VALIDATION](../provenance/RELEASE_VALIDATION.md).
