# Provenance and verification ledger

- [source_state.json](source_state.json): original source HEAD, audit target,
  tags and pre-existing staged audit status. The release has its own Git history.
- [source_inventory.csv](source_inventory.csv): hashes of the 246 source files
  tracked/staged at packaging time, using source-relative paths.
- [original_freeze_verification.json](original_freeze_verification.json):
  independent recheck of the original 72-file freeze manifest.
- [source_preservation_check.json](source_preservation_check.json): unchanged
  source file hashes, HEAD and original staging state after packaging.
- [import_inputs.json](import_inputs.json): hashes of raw files, original run
  caches, index map, and audit score/vector inputs used for portable export.
- [nonempty_export_validation.json](nonempty_export_validation.json): all 400
  nonempty-abstract query/cutoff coverage cells match the existing audit.
- [reference_values.json](reference_values.json): 1,324 reference rows,
  containing 2,572 numeric comparisons, extracted from original outputs and
  independent audit evidence. These are not generated by the new analysis.
- [RELEASE_VALIDATION.md](RELEASE_VALIDATION.md): actual release checks and limits.

`../MANIFEST.sha256` freezes public release contents. It excludes itself, Git
internals, ignored article text/model caches, and the local historical archive.
Hashes detect changes relative to this version; they are not a digital signature
or proof of scientific validity.

The original audit target `6a7415f`, packaging source `e5d96e1`, original freeze
tags and the new release commit are deliberately distinguished. In particular,
the later BGE/SPLADE and selector extensions are not silently included in the
scope of the earlier audit or this three-method research note.

The normal verification command does not regenerate expected values or the
manifest. To intentionally prepare a future version after reviewing changes,
stage its intended files, run `python3 scripts/build_manifest.py`, and then run
the verification before committing the manifest with those changes. Preserve
the old release tag and document any changed result.
